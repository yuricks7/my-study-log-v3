# Copilotのおすすめ

## 1. ロジック（hooks）のテスト

あなたは Provider を分割しているので、
ロジック単体テストがめちゃくちゃ書きやすい。

### useRecordForm

- [x] title/time の変更

- [x] バリデーション（hasInputError）

- [x] initializeForm の動作

### useRecordList

- [ ] fetchList が Supabase のデータを正しくセットするか

- [ ] sum が正しく計算されるか

### useRecordActions

- [ ] handleAdd が records を増やすか

- [ ] handleUpdate が records を更新するか

- [ ] handleDelete が records を削除するか

### useDialogState

- [ ] openDialog / closeDialog が正しく動くか

ここは UI を使わずにテストできるので、
Vitest の単体テストとして最も書きやすい。

## 2. コンポーネントのテスト

特に重要なのは EditDialog と DataTable。

### EditDialog のテスト

- [ ] openDialog → ダイアログが表示される

- [ ] closeDialog → ダイアログが閉じる

- [ ] 入力欄が title/time と連動している

- [ ] 登録ボタンを押すと handleAdd が呼ばれる

- [ ] 編集モードなら handleUpdate が呼ばれる

### DataTable のテスト

- [ ] records を正しく表示する

- [ ] レコード数が変わったら UI が更新される

## 3. 統合テスト（App.tsx）

これは「アプリ全体が動くか」を確認するテスト。

### テスト対象

- [ ] 初期ロードで Supabase のデータが表示される

- [ ] 新規登録ボタン → ダイアログが開く

- [ ] 登録 → ダイアログが閉じる

- [ ] テーブルが更新される

ここまでテストできれば、
アプリの主要機能は全部保証される。

## プロジェクトに最適なテスト順序（おすすめ）

### useRecordForm のテスト
　→ 一番簡単で、すぐ書ける

### useRecordList のテスト
　→ Supabase のモックを使う

### useRecordActions のテスト
　→ records の更新ロジックを保証する

### useDialogState のテスト
　→ 開閉の動作確認

### EditDialog のテスト
　→ UI とロジックの接続を確認

### App.tsx の統合テスト
　→ 全体の動作を保証する

この順番だと、
簡単 → 難しい → 全体の流れで進められるので、
挫折しないし、テストの価値が高い。
